# Root Cause Investigation Report

## 1. Why does the dropdown work on the homepage?
`index.html` successfully executes its JavaScript because it correctly implements the Barba.js initialization structure. Specifically, the `<body>` tag includes the `data-barba="wrapper"` attribute, and the main content wrapper includes `data-barba="container"`. The custom JavaScript bundle (`https://cdn.odyn.dev/p/vqj6/bundle.js`) hooks into the Barba.js page lifecycle events. Once Barba initializes successfully, the bundle traverses the DOM and successfully attaches the necessary event listeners to the custom `<nav class="mega-nav">` element.

## 2. Why does it work on legal pages?
The legal pages (such as `privacy-policy.html`) faithfully preserve the exact same `<body>` attributes (`data-barba="wrapper"`) and the exact same `data-wf-page="69c4a4d940fdca68c1cc9775"` attribute on the `<html>` tag as the homepage. Because the outer DOM structure and Webflow runtime IDs match `index.html` perfectly, the JavaScript execution chain completes successfully and attaches the mega-nav event listeners.

## 3. Why does it fail on generated pages?
On `financial-inclusion.html`, the `<body>` tag completely lacks the `data-barba="wrapper"` attribute (it simply has `<body class="body">`). Furthermore, the internal content wrapper lacks `data-barba="container"`. 

When the browser loads the page, `barba.umd.min.js` attempts to initialize the page transitions. Because it cannot find its mandatory wrapper element in the DOM, Barba.js crashes. This crash fatally interrupts the script execution sequence. As a result, the subsequent custom scripts in `bundle.js` that bind the click/hover event listeners to the mega-nav are never executed. 

## 4. What is the exact root cause?
The root cause is a **JavaScript runtime crash caused by missing `data-barba` attributes on the parent DOM wrappers**. 

The dropdown failure is not caused by malformed HTML inside the `<nav>` or `global_elements` itself. The `<nav>` element is structurally perfect. However, because the overarching Barba.js environment fails to initialize, the event listeners required to toggle the dropdown's visibility classes are never attached to the DOM nodes. 

A secondary contributing factor is that the Webflow page ID (`data-wf-page` on the `<html>` tag) is set to `69c4a4d640fdca68c1cc9689` instead of `69c4a4d940fdca68c1cc9775`, which prevents Webflow's native `dropship-3-0.js` from executing the standard homepage initialization sequence.

## 5. Which specific file or template introduced the defect?
The defect was definitively introduced by **`product-template.html`**. 

Whoever originally authored or exported `product-template.html` failed to configure the custom `data-barba` attributes on the `<body>` element. Because all 11 marketing pages were generated by cloning `product-template.html` as the master blueprint, this defective execution environment was systematically replicated across the entire product suite.
